# Feature Specification: 任务中控系统（Task Control Center）

**Feature Branch**: `001-task-control-center`

**Created**: 2026-10-30

**Status**: Draft

**Input**: User description: "构建一个独立的任务管理系统，包括待办任务的参数定义，任务实例入队，任务可分定时触发或按间隔时触发或立即了触发，任务运行的参数保存，任务运行成败统计，失败的需要重试机制并保留参数。这是一个任务的中控系统，本身并不实现任务，但能注册各式任务的入口，如本机脚本调用，远程ssh命令，restful接口用HTTP client触发等"

## Clarifications

### Session 2026-10-30

- Q: 第一版是否需要 Web 管理界面？ → A: 需要，第一版即包含 Web 管理界面。
- Q: 第一版 Web 管理界面需要覆盖哪些核心操作？ → A: 完整运维控制台（A）：任务定义与参数、调度、运行列表/详情、取消/重试、统计、目标与凭据管理（凭据仅管理员）。
- Q: 第一版 Web 管理界面的登录和账号体系采用哪种方式？ → A: 本地账号（B）：用户名/密码登录，使用安全哈希，管理员创建、禁用和重置用户，不接入 SSO。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 定义任务并立即执行 (Priority: P1)

作为任务运维人员，我希望先注册一个任务定义，声明参数和本机脚本入口，再用具体参数立即提交一次运行，
以便在不登录执行主机的情况下触发任务并看到结果。

**Why this priority**: 这是系统的最小可用闭环：没有任务定义、参数校验、入队、执行和结果记录，
其余调度、重试和统计能力都没有承载对象。

**Independent Test**: 创建一个带必填参数和可选参数的本机脚本任务定义，提交合法参数后观察运行从
排队进入执行并到达终态，核对参数快照、退出码和输出；再用缺失或非法参数提交，确认被拒绝且不产生运行。

**Acceptance Scenarios**:

1. **Given** 一个已启用、带必填参数的本机脚本任务定义，**When** 已认证操作员提交合法参数，**Then**
   系统创建运行、完成参数校验、进入队列并执行，最终可查询状态、参数快照、耗时和结果。
2. **Given** 参数缺失、类型错误或超出约束，**When** 操作员提交运行，**Then** 系统拒绝提交并返回
   字段级错误，且不创建任务实例。
3. **Given** 本机脚本以非零退出码结束，**When** 运行结束，**Then** 运行标记为失败并保留退出码、
   错误分类和受大小限制的输出摘要。
4. **Given** 操作员已提交运行，**When** 运行处于排队或执行中，**Then** 可查询其当前状态及每次执行尝试。

### User Story 2 - 配置定时、间隔与一次性调度 (Priority: P2)

作为任务运维人员，我希望把任务定义为在指定时间执行一次、按固定间隔重复或按日历规则重复，
并可以暂停、恢复和取消，以便无人值守地运行周期性任务。

**Why this priority**: 调度是中控系统区别于手工执行器的核心价值，但它依赖 P1 的定义、入队和执行闭环。

**Independent Test**: 创建一个一分钟后的单次调度和一个短间隔调度，观察触发时间、下一次触发时间、
暂停/恢复/取消行为；在服务停止期间跨过触发点后重启，核对错过触发的记录和处理结果。

**Acceptance Scenarios**:

1. **Given** 一个未来时间点的一次性调度，**When** 到达该时间点且服务健康，**Then** 系统只创建一个
   运行并进入队列，调度在触发后标记为已完成。
2. **Given** 一个固定间隔或日历规则调度，**When** 每次到期，**Then** 系统按配置的时区计算并在目标
   精度内创建运行，且下一次触发时间可查询。
3. **Given** 一个活动调度，**When** 操作员暂停、恢复或取消它，**Then** 暂停期间不产生新运行，
   恢复后从下一个到期点继续，取消后不再产生运行且历史运行保留。
4. **Given** 上一次运行尚未结束，**When** 同一调度再次到期，**Then** 系统按重叠策略跳过或排队，
   并将跳过原因记录为可查询的事件。
5. **Given** 服务在调度到期期间不可用，**When** 服务恢复，**Then** 系统记录错过的触发，并按错过
   策略在宽限期内补跑一次或标记为错过，不重复补跑同一次触发。

---

### User Story 3 - 通过 SSH 和 HTTP 触发远程任务 (Priority: P3)

作为任务运维人员，我希望在任务定义中注册远程 SSH 命令或 HTTP 请求入口，并使用受控的凭据执行，
以便中控系统统一触发不同技术栈的任务，而不需要在每台机器上部署执行器。

**Why this priority**: 远程入口是“注册各式任务入口”的关键能力，但本地执行闭环已经能独立交付价值。

**Independent Test**: 分别注册一个 SSH 任务和一个 HTTP 任务，使用测试主机和测试端点提交运行；
验证成功、认证失败、连接失败、超时和非预期响应均得到正确分类，且响应和日志不泄露凭据。

**Acceptance Scenarios**:

1. **Given** 一个引用已登记主机和凭据的 SSH 任务定义，**When** 提交运行，**Then** 系统按配置连接、
   执行命令、校验主机身份、应用超时，并记录退出码和输出摘要。
2. **Given** 一个引用已登记端点的 HTTP 任务定义，**When** 提交运行，**Then** 系统按配置的方法、地址、
   请求头、请求体和超时发送请求，并按状态码及可选响应条件判断成功或失败。
3. **Given** 目标主机或端点未登记、凭据无效、证书校验失败或网络不可达，**When** 提交运行，
   **Then** 运行失败并给出可区分的错误分类，且不向调用方返回任何凭据值。
4. **Given** 任务提交者试图在参数中指定任意主机、URL 或命令，**When** 目标不在管理员登记的允许范围内，
   **Then** 系统拒绝该提交。

### User Story 4 - 失败自动重试并保留原始参数 (Priority: P4)

作为任务运维人员，我希望可重试的失败按策略自动重试，重试时使用第一次提交时的参数和任务定义版本，
并保留每次尝试的记录；重试耗尽后可以手工再次提交且无需重新填写参数。

**Why this priority**: 失败重试是用户明确要求的可靠性能力，但必须在 P1 的执行与结果记录之上实现。

**Independent Test**: 定义一个前两次失败、第三次成功的任务，提交后核对三次尝试使用完全相同的参数快照、
定义版本和目标配置，最终运行成功；再让重试耗尽，执行手工重试并核对新运行与原运行的关联关系。

**Acceptance Scenarios**:

1. **Given** 一个配置了重试策略的任务定义，**When** 运行因超时、连接失败或可重试的服务端错误失败，
   **Then** 系统按退避策略自动重试，直到成功或达到最大尝试次数。
2. **Given** 任一自动重试，**When** 检查该次尝试，**Then** 其参数快照、任务定义版本和执行目标与首次尝试一致，
   不会重新解析默认值或使用更新后的定义。
3. **Given** 运行因参数校验、认证、权限、主动取消或不可重试的客户端错误失败，**When** 运行结束，
   **Then** 系统不自动重试，并记录不可重试原因。
4. **Given** 重试次数耗尽，**When** 最后一次尝试失败，**Then** 运行进入最终失败状态并保留全部尝试记录，
   不再产生新的自动尝试。
5. **Given** 一个最终失败或已完成的运行，**When** 有权限的操作员执行手工重试，**Then** 系统创建
   关联原运行的新运行，复制原参数快照和定义版本，原运行记录保持不可变。

### User Story 5 - 查看运行成败统计与失败详情 (Priority: P5)

作为任务运维人员，我希望按任务定义、时间范围、触发方式和执行入口查看运行数量、成功率、耗时和失败原因，
并能从统计下钻到具体运行和尝试，以便定位不稳定任务并评估重试效果。

**Why this priority**: 统计依赖前面所有运行和尝试数据，是运营和持续改进能力，不是最小闭环的阻塞项。

**Independent Test**: 构造已知数量的成功、失败、取消和重试运行，查询统计并与运行/尝试明细逐项核对；
验证筛选、分页和下钻结果一致，重试不会重复计入运行总数。

**Acceptance Scenarios**:

1. **Given** 一组已完成的运行，**When** 查询统计，**Then** 返回总数、成功数、失败数、取消数、跳过数、
   错过数和重试中数量，以及成功率和执行耗时指标。
2. **Given** 同一运行包含多次尝试，**When** 查询运行统计，**Then** 该运行只计一次；尝试级成功/失败
   另行统计，不改变运行级分母。
3. **Given** 按任务定义、版本、触发方式、执行入口、状态和时间范围筛选，**When** 查询统计，
   **Then** 结果只包含匹配数据，并可下钻到对应运行和尝试。
4. **Given** 运行刚刚结束，**When** 在数据新鲜度目标内查询统计，**Then** 统计结果包含该运行且与明细一致。

---

### User Story 6 - 通过 Web 管理界面完成任务运维 (Priority: P1)

作为任务运维人员，我希望在浏览器中完成任务定义、提交、调度、查看运行、重试和统计，以及由管理员
完成目标、凭据、用户和角色分配，以便不依赖 API 也能完成日常工作。

**Why this priority**: 用户明确要求第一版包含完整运维控制台；它是 v1 的交付渠道，不是后续增强。

**Independent Test**: 使用已认证管理员账号，仅通过 Web 界面创建带动态参数的任务定义、提交运行、
配置调度、查看结果、重试失败运行、查看统计，登记和禁用一个执行目标与凭据引用，并创建、禁用、
重置一个用户和分配角色；再用操作员和只读账号确认管理页面不可见、写操作入口不可用，且直接请求
被服务端拒绝。

**Acceptance Scenarios**:

1. **Given** 已认证操作员，**When** 打开 Web 界面，**Then** 能看到任务定义、调度、运行和统计入口，
   管理员还能看到目标、凭据、用户与角色分配入口；空数据时有明确的创建或筛选引导。
2. **Given** 带参数结构的任务定义，**When** 在界面创建或编辑并提交，**Then** 表单按参数类型生成、
   校验错误就地显示，保存后新版本可见。
3. **Given** 一个运行或统计结果，**When** 执行取消、重试或下钻，**Then** 关键操作需要确认、
   反馈明确，结果与 API 一致。
4. **Given** 管理员，**When** 登记、编辑或禁用执行目标和凭据引用，或创建、禁用、重置用户并分配角色，
   **Then** 操作成功且界面只显示掩码后的凭据元数据，任何明文凭据都不会出现在页面、日志或接口响应中。
5. **Given** 操作员或只读观察者，**When** 访问目标/凭据/用户管理页面或写操作，**Then** 界面隐藏或
   禁用入口，直接请求也被服务端拒绝并记录审计。
6. **Given** 桌面或移动屏幕，**When** 浏览常用页面，**Then** 布局可用、键盘可导航、
   状态和错误信息清晰可读。

---

### Edge Cases

- 任务定义被禁用、归档或删除时，已有调度、待执行运行、执行中运行和历史运行应如何处理？
- 任务定义在调度创建后发生新版本时，调度应继续使用固定版本还是自动切换到最新版本？
- 两个操作员同时编辑同一任务定义、调度或用户时，如何避免静默覆盖其中一方的修改？
- 同一调度在极短时间内连续到期，或同一任务定义存在多个调度同时到期时，如何避免重复和惊群？
- 服务在运行执行中重启时，如何识别失联运行、避免永久停留在“执行中”，并决定是否重试？
- 调度到期时服务不可用、系统时钟跳变或进入夏令时，如何避免重复触发或永久错过？
- 上一次运行未结束时，重叠策略为跳过或排队分别应产生什么可查询记录？
- SSH 主机密钥变化、认证失败、命令超时、进程被信号终止时，错误如何分类和展示？
- HTTP 返回 3xx、4xx、5xx、非预期响应体、TLS 失败或连接超时时，成功判定和重试分类是否明确？
- 重试期间任务定义被修改、凭据被轮换或目标被移出允许列表时，重试应使用哪一份配置？
- 运行被取消时恰好正在执行或正在等待重试，如何保证终态唯一且不会继续产生尝试？
- 参数、输出或日志中包含密钥时，如何避免在 API、统计和审计中泄露？
- 输出超过保留上限时，如何截断、标记并仍保留足够的失败诊断信息？
- 重复提交、网络重试或客户端超时后重发时，如何保证不会产生重复运行？
- 队列积压或全局并发饱和时，如何保证运行不丢失、顺序可解释且状态可见？
- 归档或删除任务定义后，历史统计和审计是否仍可查询？

## Requirements *(mandatory)*

### Functional Requirements

**任务定义与注册**

- **FR-001**: 系统 MUST 允许有权限的操作员创建、查看、修改、启用、禁用和归档任务定义；每个定义
  必须有稳定且唯一的业务键，每次修改生成不可变的新版本。
- **FR-002**: 任务定义 MUST 声明带类型的参数结构，至少支持字符串、整数、小数、布尔、日期时间、
  枚举和敏感值；每个参数可声明必填、默认值、取值范围/长度/格式约束。
- **FR-003**: 系统 MUST 在保存任务定义时校验参数结构、执行入口配置、超时和重试策略的合法性，
  并拒绝无效定义。
- **FR-004**: 系统 MUST 内置本机脚本、远程 SSH 命令和 HTTP 请求三类执行入口，并允许管理员为每个
  任务定义选择其中一类及配置目标。
- **FR-005**: 系统 MUST 提供受控的执行入口扩展点，使新增入口类型可以复用现有的参数校验、排队、
  调度、重试和统计能力，而无需修改这些通用能力。
- **FR-006**: 新提交的运行 MUST 默认使用任务定义的最新启用版本；调度计划和已有运行 MUST 固定引用
  创建时的定义版本，后续定义修改不得静默改变它们的参数结构或执行目标。
- **FR-007**: 禁用任务定义 MUST 阻止新的提交，并暂停其关联调度；尚未到期的 `scheduled` 运行 MUST
  被取消并记录 `DEFINITION_DISABLED`；已 `queued/running/retry_wait` 的运行默认继续，可由操作员
  显式取消。重新启用后 MUST 由操作员显式恢复调度，不得自动补跑禁用期间的全部触发。
- **FR-008**: 归档或删除任务定义 MUST 阻止新的提交和调度，但保留其历史运行、尝试、统计和审计记录，
  不得破坏历史数据的可查询性；归档 MUST 取消尚未开始的排队运行，执行中的运行允许完成并保留结果。
- **FR-009**: 管理员 MUST 能登记允许的 SSH 主机和 HTTP 端点及其凭据引用；任务定义只能引用已登记的
  目标，提交者不得在参数中临时指定任意主机、URL 或可执行命令。管理员禁用目标或凭据后，新的提交和
  后续重试 MUST 被拒绝；已 `queued` 或 `retry_wait` 的运行 MUST 标记失败并记录 `TARGET_DISABLED`；
  已 `running` 的运行允许完成；未到期的 `scheduled` 运行在提升时 MUST 重新校验并在目标/凭据禁用时
  失败，不得执行。
- **FR-010**: 系统 MUST 提供任务定义列表，支持分页、按名称/业务键/状态/执行入口筛选和排序。

**提交、参数与队列**

- **FR-011**: 系统 MUST 允许有权限的操作员基于任务定义提交一次运行，校验参数后生成不可变的运行记录，
  保存解析后的参数快照、定义版本、执行入口类型和目标引用。
- **FR-012**: 运行的提交 MUST 支持立即触发和指定时间一次性触发；按固定间隔和日历规则重复触发
  MUST 由调度计划创建运行。
- **FR-013**: 调度 MUST 允许每个计划配置时区；所有时间点 MUST 以 UTC 存储，触发计算和展示 MUST
  使用计划配置的时区，并正确处理夏令时和时钟调整。
- **FR-014**: 提交运行 MUST 支持可选的幂等键；相同幂等键的重复提交 MUST 返回已有运行，不得产生
  重复执行。
- **FR-015**: 系统 MUST 将待执行运行放入队列，并按任务定义的并发上限和全局并发上限控制执行；
  超限运行 MUST 保持排队且状态、位置或排队原因可查询。
- **FR-016**: 同一任务定义内 MUST 按入队时间 FIFO；跨任务定义 MUST 在全局并发上限内优先选择最早
  可执行的运行，并跳过已达定义并发上限的运行；不得因某个定义饱和而阻塞其他定义。
- **FR-017**: 操作员 MUST 能取消待执行、排队中、等待重试或执行中的运行；执行中的取消 MUST 尽力
  终止执行，无法终止时 MUST 记录实际结果和取消请求。
- **FR-018**: 已取消或已进入最终状态的运行 MUST NOT 自动重试或再次执行。
- **FR-019**: 系统 MUST 提供运行列表和详情，支持按任务定义、版本、状态、触发方式、执行入口、
  时间范围筛选和分页。

**调度**

- **FR-020**: 调度器 MUST 在到期时为一个触发点最多创建一个运行；同一触发点不得因服务多实例、
  重试或重启而重复创建。
- **FR-021**: 调度 MUST 支持暂停、恢复和取消；系统 MUST 展示下一次触发时间和当前调度状态；
  一次性调度触发后 MUST 进入已完成状态。
- **FR-022**: 每个调度 MUST 配置重叠策略；默认 MUST 为跳过，即上一次运行未结束时记录一次带原因的
  跳过事件；也 MUST 支持排队等待。
- **FR-023**: 服务不可用期间错过的触发 MUST 被记录；恢复后 MUST 对宽限期内的错过触发最多补跑一次
  （合并为一次运行），超出宽限期的触发标记为错过；补跑不得重复执行同一触发点。
- **FR-024**: 日历规则和固定间隔 MUST 在配置时区内计算；夏令时切换、时钟回拨或前跳不得造成
  重复触发或永久错过。
- **FR-025**: 调度计划 MUST 保存提交时的参数快照和定义版本；修改调度参数或版本 MUST 形成可见变更，
  不得静默影响已创建的历史运行。

**执行**

- **FR-026**: 每次执行 MUST 通过执行入口适配器完成，并应用任务定义的超时；系统 MUST 记录开始时间、
  结束时间、执行时长和终态。服务重启后 MUST 对账处于执行中的运行，无法确认结果时记录为失败或未知
  并按重试策略处理，不得永久停留在执行中。
- **FR-027**: 本机脚本入口 MUST 支持配置解释器、脚本/命令、工作目录和环境变量；参数 MUST 以结构化
  参数或环境变量传递，不得把未转义的用户输入拼接进 shell 命令文本。
- **FR-028**: SSH 入口 MUST 支持配置主机、端口、用户、凭据引用和远程命令；系统 MUST 校验主机身份，
  MUST 应用连接/执行超时，并记录退出码和输出摘要；主机密钥变化 MUST 默认拒绝执行并记录，
  除非管理员显式更新信任。
- **FR-029**: HTTP 入口 MUST 支持配置方法、地址、请求头、请求体、凭据引用和超时；系统 MUST 校验
  TLS 证书，并支持按配置的成功状态码范围及可选的响应头/响应体条件判断成功。
- **FR-030**: 系统 MUST 对标准输出、标准错误或 HTTP 响应体设置保留上限，超限时截断并标记；
  敏感值 MUST 在输出、日志、统计和 API 响应中被遮蔽。
- **FR-031**: 超时或取消 MUST 尽力终止本机进程、SSH 执行或 HTTP 请求，并分别记录为超时或取消；
  不得把无法确认的结果虚报为成功。
- **FR-032**: 每次执行尝试 MUST 记录状态、执行目标、开始/结束时间、退出码或 HTTP 状态码、错误分类、
  执行时长和输出摘要；运行详情 MUST 能展示所有尝试。

**重试**

- **FR-033**: 任务定义 MUST 支持配置重试策略，至少包括最大尝试次数、初始退避、退避倍数、最大退避
  和可重试错误分类；系统 MUST 为未配置的任务定义提供明确的默认策略。
- **FR-034**: 系统 MUST 仅对可重试失败自动重试，至少包括超时、连接失败、执行目标暂时不可用、
  HTTP 429 和 5xx；参数校验失败、认证/权限失败、主动取消以及其他 HTTP 4xx（408、429 除外）
  MUST NOT 自动重试。
- **FR-035**: 自动重试 MUST 使用首次提交时解析并保存的参数快照、任务定义版本和执行目标配置，
  不得重新解析默认值、改用最新定义或丢失参数；凭据引用 MUST 在每次尝试时解析当前有效凭据，
  参数快照不得包含密钥明文。
- **FR-036**: 每次自动重试 MUST 生成独立尝试记录并递增尝试序号；运行的尝试次数、下一次重试时间和
  当前状态 MUST 可查询。
- **FR-037**: 重试耗尽后运行 MUST 进入最终失败状态并保留全部尝试；系统 MUST NOT 无限重试或静默丢弃
  失败运行。
- **FR-038**: 有权限的操作员 MUST 能对失败或已结束运行执行手工重试；手工重试 MUST 创建关联原运行的
  新运行并复制原参数快照和定义版本，原运行记录不可修改。

**统计与可观测性**

- **FR-039**: 系统 MUST 提供运行统计，至少包括总数、成功数、失败数、取消数、跳过数、错过数、
  重试中数量、成功率、平均执行时长和 P95 执行时长。
- **FR-040**: 运行成功率 MUST 等于成功运行数除以“成功运行数 + 失败运行数”；取消、跳过和错过 MUST
  单独展示且不计入该分母。运行级统计 MUST 以最终状态计数，重试不得重复计入运行总数；尝试级
  成功/失败 MUST 单独统计。
- **FR-041**: 统计 MUST 支持按任务定义、定义版本、触发方式、执行入口、状态、调度计划和时间范围筛选，
  并 MUST 支持从聚合结果下钻到运行和尝试明细。
- **FR-042**: 统计 MUST 在运行结束后 60 秒内反映新数据；明细和聚合的保留期限 MUST 可配置，
  默认保留明细至少 90 天、聚合至少 13 个月。
- **FR-043**: 所有时间统计 MUST 以 UTC 为存储基准，查询 MUST 接受调用方时区并按该时区返回时间边界。

**安全、审计与接口**

- **FR-044**: 除健康检查外，所有管理和执行接口 MUST 要求身份认证；系统 MUST 至少区分管理员、
  操作员和只读观察者角色，并在服务端执行资源级授权。管理员 MUST 能管理用户、目标、凭据和全局配置；
  操作员 MUST 能管理任务定义、调度以及提交、取消和重试运行；只读观察者 MUST 只能查看。
- **FR-045**: 敏感值 MUST 通过凭据或密钥引用使用，MUST 加密存储或委托给密钥管理服务，
  MUST NOT 在 API、日志、统计、错误信息或审计中返回明文。
- **FR-046**: 系统 MUST 记录任务定义/版本、目标/凭据、调度、提交、取消和重试的审计事件，至少包含
  操作者、动作、资源、时间、结果和关联运行标识。
- **FR-047**: 系统 MUST 校验所有外部输入并限制请求和输出大小；错误响应 MUST 使用稳定错误码、
  可读消息和关联标识，MUST NOT 暴露内部异常堆栈。
- **FR-048**: 列表接口 MUST 使用一致的分页、排序和筛选约定；系统 MUST 提供 OpenAPI 文档，
  不兼容变更 MUST 在 `docs/api-compatibility.md` 记录影响范围、迁移步骤和回滚方案。
- **FR-049**: 面向操作员的 API 响应（以及维护 CLI 的输出）MUST 清楚展示运行状态、失败原因和
  建议的下一步操作，使操作员无需登录执行主机即可判断是否需要重试或修改配置。
- **FR-050**: 系统 MUST NOT 接受运行时代码或任意执行入口插件的上传；新增执行入口类型 MUST 通过
  受控的代码扩展和部署流程完成。

**Web 管理界面**

- **FR-051**: 系统 MUST 提供 Web 管理界面，覆盖任务定义与参数、调度、运行列表/详情、取消/重试、
  统计，以及仅管理员可见的目标、凭据、用户与角色分配，并与 API 使用同一套认证、授权和业务规则。
- **FR-052**: Web 界面 MUST 根据任务定义的参数结构生成参数表单，支持必填/可选、默认值、枚举和
  敏感值输入，并在提交前展示字段级校验错误。
- **FR-053**: Web 界面 MUST 为数据加载、空状态、操作成功、操作失败和并发冲突提供明确反馈；
  删除、取消、归档和手工重试等关键操作 MUST 要求确认，并防止重复提交。
- **FR-054**: Web 界面 MUST 支持常见桌面和移动屏幕尺寸，并满足基本的键盘导航、可读对比度和
  表单标签等无障碍要求。
- **FR-055**: Web 界面 MUST 对无权限操作隐藏或禁用入口，同时服务端 MUST 再次执行权限校验；
  越权请求 MUST 被拒绝并记录审计。
- **FR-056**: Web 界面 MUST 展示运行状态、失败原因、尝试次数、下一次触发时间和统计结果，
  并支持从统计下钻到运行及尝试详情。
- **FR-057**: Web 界面 MUST NOT 显示或回传凭据明文；管理员只能创建/更新凭据引用、查看掩码后的
  元数据并禁用凭据，所有变更 MUST 记录审计。
- **FR-058**: 第一版 MUST 使用本地账号体系：用户名 MUST 唯一，管理员 MUST 能创建、禁用、重置密码
  和分配角色；系统 MUST NOT 提供自助注册；密码 MUST 使用安全哈希存储，MUST 支持用户修改密码和
  管理员重置密码。
- **FR-059**: 系统 MUST 对连续失败登录实施锁定，并 MUST 支持会话过期、退出登录和服务端吊销；
  Web 会话 MUST 使用 HttpOnly、Secure、SameSite Cookie 或等效的安全令牌机制，系统 MUST 防范
  CSRF 和 XSS；密码、会话令牌和重置凭据 MUST NOT 出现在日志、审计或错误信息中。
- **FR-060**: 登录成功/失败、账号锁定、密码修改/重置、角色变更和会话吊销 MUST 记录审计，
  至少包含操作者、时间、来源和结果。
- **FR-061**: 并发修改任务定义、调度或用户时，系统 MUST 使用版本检查或等效的乐观并发控制；
  冲突 MUST 被拒绝并提示重新加载，MUST NOT 静默覆盖他人修改。
- **FR-062**: 系统 MUST 对登录和写操作实施速率限制或等效的滥用防护；超限请求 MUST 返回标准错误
  并记录审计。
- **FR-063**: 系统 MUST 提供不暴露敏感信息的健康检查和就绪检查，供部署编排和监控使用；
  就绪状态 MUST 反映数据库、调度器等关键依赖的可用性。

### Key Entities *(include if feature involves data)*

- **任务定义（Task Definition）**: 可复用的任务模板，包含稳定业务键、名称、说明、当前启用版本、
  执行入口类型、参数结构、超时、默认重试策略、并发上限、状态和审计时间。
- **任务定义版本（Task Definition Version）**: 任务定义在某一时刻的不可变快照，包含参数结构、
  执行入口配置和默认策略；运行和调度必须引用明确版本。
- **执行目标（Execution Target）**: 管理员登记的本机脚本、SSH 主机或 HTTP 端点配置，包含地址、
  超时、允许状态和凭据引用；不含凭据明文。
- **凭据引用（Credential Reference）**: 指向密钥管理服务或受保护存储的引用，仅暴露名称、用途和
  可用状态，不暴露密钥值。
- **调度计划（Schedule）**: 绑定任务定义版本和参数快照的触发配置，包含触发方式（一次性/日历/间隔）、
  时区、下一次触发时间、重叠策略、错过策略和状态。
- **任务运行（Task Run）**: 一次提交产生的任务实例，包含引用的定义版本、参数快照、触发方式、
  幂等键、状态、计划时间、排队时间、开始/结束时间、最终结果、尝试次数和原运行关联。
- **执行尝试（Task Attempt）**: 运行的一次实际执行，包含尝试序号、执行目标、状态、开始/结束时间、
  退出码或 HTTP 状态码、错误分类、执行时长和输出摘要。
- **审计事件（Audit Event）**: 对定义、目标、调度、提交、取消和重试等关键动作的记录，包含操作者、
  动作、资源、时间、结果和关联标识。
- **用户账号与角色（User Account and Role）**: 本地账号，包含唯一用户名、角色、启用状态、
  安全哈希后的密码凭据、最近登录时间和失败计数；不包含密码明文。

运行状态至少包括 `scheduled`、`queued`、`running`、`retry_wait`、`succeeded`、`failed`、
`cancelled`、`skipped` 和 `missed`；终态为 `succeeded`、`failed`、`cancelled`、`skipped` 和
`missed`。调度状态至少包括 `active`、`paused`、`completed` 和 `cancelled`。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有权限的操作员可以在 2 分钟内完成“创建带至少 5 个参数的任务定义并立即提交一次运行”，
  并看到终态结果（执行时间不超过 60 秒的任务）。
- **SC-002**: 在容量充足时，99% 的立即触发运行在提交后 10 秒内开始执行。
- **SC-003**: 服务健康时，99% 的调度触发点在到期后 5 秒内完成入队。
- **SC-004**: 100% 的自动重试使用与首次尝试完全相同的参数快照、定义版本和执行目标配置；
  可通过尝试记录逐字段核对。
- **SC-005**: 100% 的运行和尝试具有完整的状态、时间戳和结果元数据；服务重启后 5 分钟内完成失联
  运行的对账，不出现永久停留在执行中的运行。
- **SC-006**: 在安全验证中，API 响应、日志、统计和审计记录暴露的明文敏感值为 0。
- **SC-007**: 系统在至少 1,000 个任务定义、10,000 个待执行/已调度运行和 100 个并发执行的目标负载下，
  不丢失、不重复创建调度触发。
- **SC-008**: 在相同筛选条件下，成功/失败统计与底层运行/尝试明细的核对一致率为 100%。
- **SC-009**: 使用相同幂等键重复提交时，100% 的测试场景只产生一个运行。
- **SC-010**: 在至少 10 名操作员参与的可用性测试中，至少 90% 的人能独立定位失败原因并发起手工重试，
  无需工程人员协助。
- **SC-011**: 至少 90% 的操作员能在不借助 API 的情况下，通过 Web 界面完成“创建任务定义、
  提交运行、配置调度、查看结果、重试失败运行”的完整流程。
- **SC-012**: 在目标负载下，95% 的常用页面（任务列表、运行详情、统计）在 2 秒内展示可用的首屏内容。
- **SC-013**: Web 界面的所有写操作均在服务端执行权限校验；越权尝试 100% 被拒绝并产生审计记录。
- **SC-014**: 管理员能在 Web 界面完成执行目标和凭据引用的登记、禁用与审计查看；页面和接口响应中
  出现凭据明文的次数为 0。
- **SC-015**: 管理员能在 Web 界面完成用户创建、禁用、密码重置和角色分配；系统不存在自助注册入口。
- **SC-016**: 在安全验证中，密码明文存储、日志泄露和会话令牌泄露为 0；连续失败登录达到策略阈值后
  账号按预期锁定，退出登录和会话过期后旧会话不可继续使用。
- **SC-017**: 并发编辑同一任务定义、调度或用户时，100% 的冲突被检测并拒绝，不出现静默覆盖。
- **SC-018**: 认证和写操作在超过配置阈值后按预期限流；100% 的超限请求返回标准错误并产生审计记录。
- **SC-019**: 部署编排能在 30 秒内通过健康/就绪检查判断实例是否可用；检查响应不包含敏感信息。

## Assumptions

- 系统作为内部、单工作区的任务中控面部署；所有已认证操作员共享任务视图，通过角色控制写操作，
  不包含面向公众的多租户 SaaS 场景。任务定义、调度和运行属于工作区共享数据，不按个人隔离；
  工作区边界即数据隔离边界。
- 第一版同时交付完整运维控制台和 REST API；Web 界面与 API 共用同一套认证、授权和业务规则，
  覆盖任务定义与参数、调度、运行、重试、统计，以及仅管理员可见的目标、凭据、用户与角色分配。
  第一版界面语言为中文，术语与 API 保持一致。运维自动化通过 API/脚本完成，不交付独立运维 CLI；
  `cli.py` 仅用于部署引导和维护命令（create-admin、reset-password、retention 触发）。
- 第一版使用本地账号体系，管理员创建、禁用、重置用户并分配角色；不接入 SSO/OIDC，不提供自助注册。
  默认密码至少 12 位并拒绝常见弱密码，连续 5 次失败锁定 15 分钟，会话空闲 30 分钟过期、
  绝对有效期 8 小时。
- 执行入口以本机脚本、SSH 和 HTTP 三类内置能力为主；新增入口类型通过受控代码扩展和部署完成，
  不提供运行时代码上传或插件市场。
- 第一版采用单控制面部署，不包含分布式执行器集群、跨区域多活或工作流 DAG 编排；远程目标由
  外部系统提供并通过 SSH/HTTP 访问。
- 默认调度时区为 UTC，单个调度可覆盖；默认重试为最多 3 次尝试，初始退避 30 秒、倍数 2、
  最大退避 10 分钟；默认每个任务定义并发上限为 1，全局并发上限由部署配置决定。
- 默认重叠策略为跳过，默认错过宽限期为 1 小时并在宽限期内合并补跑一次；默认单次输出保留上限为
  1 MB，超限截断并标记。HTTP 默认仅将 2xx 视为成功，是否跟随重定向由任务定义配置。
- 默认保留运行/尝试明细 90 天、聚合统计 13 个月，均可配置；审计记录保留期限不少于运行明细。
- 系统依赖可用的密钥管理或受保护凭据存储、可访问的 SSH/HTTP 目标以及同步的系统时钟；
  这些外部依赖不属于本系统的实现范围。身份认证由系统自身的本地账号提供。
- 任务定义、调度和手工重试由受信任的运维人员操作；任务提交者不得绕过定义直接指定任意命令、
  主机或 URL。
- 第一版不提供任务优先级、任务间依赖、审批流或资源配额；每个运行按提交/触发顺序独立处理。

## Out of Scope

- 实现具体业务任务的逻辑；中控系统只负责注册入口、调度、执行、重试和记录。
- 任务依赖图、DAG、扇入/扇出、条件分支、人工审批和跨任务编排。
- 分布式执行器集群、跨区域容灾、主动-主动高可用和容器编排平台集成。
- 移动端原生应用、计费和面向公众的运营门户；Web 管理界面属于第一版范围。
- 企业 SSO/OIDC 集成、自助注册和多因素认证（MFA）；第一版使用本地账号。
- 运行时插件上传、任意脚本市场或允许非管理员注册新的可执行入口类型。
- 任务优先级调度、资源配额、成本核算和基于优先级的抢占。
- 邮件、短信、即时通讯或值班系统告警集成；第一版只提供统计和运行详情查询。
- 集中式日志平台、指标平台或链路追踪平台的实现与运维。
- 现有历史任务数据的迁移；如需迁移，应作为独立特性规划。
